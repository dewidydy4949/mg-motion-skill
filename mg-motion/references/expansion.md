# 新增参考或稳定实现

新增素材可以先成为参考：保留原始上下文、来源、关键时间点、实际可访问文件、可借鉴的方法与边界。更新 reference-library.json 的表达分类、学习点、取舍理由和证据；默认参考集按覆盖与近重复取舍，不要求每个新素材都占默认名额。新参考若尚无稳定实现，应先在独立项目里验证，不伪造已注册模板或把缺失视频当作存在。

现有 refs 索引绑定已注册模板；新的纯参考资料先在项目 brief 中记录，待实际需要时再扩展索引结构。下面流程适用于确实要加入稳定可执行模板的情况。

先确定参考片的一个完整功能段，记录源文件、起止秒和关键运动。全片总览用于定位，密集动作帧和原尺寸关键帧用于决定坐标、层次、进出场与停留。原片的主旨和运动结构优先于装饰细节。

同时记录复用边界：这是哪一种表达关系，哪些判断来自原场景，哪些背景、布局、文字或动作不可替换。示例标语、章节编号、问句和业务阈值应可显式设置或关闭；不要在通用组件里自动补标点、改变语气或默认带出示例话术。指标计数和步骤编号应区分。

新模板使用 `assets/engine/src/batch/MG-xxx/` 下独立目录：

- `model.tsx` 导出 `Template` 和 `validateProps`；组件也调用校验，不能只在默认数据时检查。
- `demo.ts` 导出 `referenceProps`、`usageProps`，分别演示参考结构与明显不同的中文业务内容。
- `entry.tsx` 注册独立参考/复用 compositions，`calculateMetadata` 从实际传入参数计算时长，禁止丢弃用户参数。

所有动画由帧数决定，避免随机数、当前时间和 CSS 自运行动画。提供合理的文字、条目、数值与时长边界。先确认中文与宽英文在边界内容下的实际排版，再定验证限制；不能只限制字符数而忽略宽度。

共享绘制工具放在有版本语义的目录，纯函数为主。一个共享卡片布局不等于多个不同模板；比较、表格、轮播、滚动数值、层级和路径等需要匹配各自的信息结构与运动。

为新模板实际渲染两组不同内容，检查关键帧、边界参数和收尾。交付样片、复用片、原片对照、参数 JSON、使用卡、源码与 meta。meta 记录实际检查、差异和限制，不写未经执行的检查，不将批量授权写成用户逐条看过。

入库时在 `src/skill/registry.ts` 导入组件/校验函数，在 `src/skill/data.json` 添加两组默认值、durationKey、实际时长与固定时长限制，更新 `references/catalog.json`、`references/selection.json`、`references/compatibility.json`、`references/reference-library.json` 和 `assets/params/`、使用卡。选择目录要记录实际用途、常用检索词、素材槽绑定方式、内容容量、时长行为及不适用情况。风格族只标注实际兼容的设计，不凭“深色”“科技”等宽泛词合并。保持模板 ID 唯一；更改共享源需重新生成受影响模板哈希和检查记录。

新增后执行 TypeScript 检查、参数校验、正常输入渲染、应拒绝的边界输入，再实看画面。若多个作者并行，先分配不重复编号和目录，每人仅改自己目录；由集成者更新注册表与目录。
